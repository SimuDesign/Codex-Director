> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. In this workspace use the installed local executing-plans workflow; unavailable superpowers tools are not required. The user approved local implementation on 2026-11-05; Git publication remains separately gated.

**Goal:** 从首页查看近 7／30／60 天已观察到的周额度使用、单日依据及有证据的周期切换，清楚表达重置时间、缺测与可计算范围。

**Architecture:** 首页继续使用现有七日缓存和实时当前值；历史详情惰性读取现有 SQLite 中同一来源的周额度记录，一次构建固定 60 日上下文，三个范围只作内存切片。使用独立 DTO、偏好和窗口会话状态，不把实时读取伪装成历史，不增加历史采集器、数据库或索引任务。

**Tech Stack:** Swift 6、Foundation、现有 SQLite actor、SwiftUI/AppKit、Swift Charts、既有 Scheme A 组件与 XCTest；无新第三方依赖或云服务。

## 1. 用户任务与首版范围

用户能回答：最近哪些日期使用较多、记录是否连续、哪些日期无法计算，以及账户报告的下一次重置时间和记录中可确认的周期切换。

### 包含

1. 首页额度模块增加有文字的“额度历史 / Quota history”入口，打开一个原生 Sheet。
2. 独立的近 7／30／60 天选择器；默认 30 天，记住有效选择。
3. 所选来源的周额度每日已观察使用增量、按日记录和原位单日说明。
4. 当前有效的周／五小时剩余及各自账户报告的下次重置时间，复用现有当前值链路。
5. 历史记录中的已确认周期切换标记及前后观测区间。
6. 有记录天数、可计算天数、当前值采集时间、历史最后观察时间和查询截至时间。

### 不包含

- 五小时的历史趋势、实时快照持续落盘、账号识别或跨账号历史隔离。
- 额外源扫描、历史重解析、改变菜单栏刷新频率、第二套索引器或被动轮询。
- Token／费用换算、按 Agent／项目分摊额度、耗尽预测、平均效率或能力有效性结论。
- 跨来源合计、60 天“总使用百分比”、把缺测纳入日均分母、自动补齐历史。
- 任意日期范围、历史专属来源浏览、额外周期 Tab、独立一级额度页面、数据导出。

## 2. 当前系统事实与限制

- `quota_snapshots` 保存采集时间、窗口、使用比例、报告重置时间和来源；没有固定 60 天保留上限，但它属于可清除的派生索引。
- 当前历史来自已索引的本地额度记录；已有记录的跨度不证明每天完整覆盖，也不证明所有日期都可计算。
- app-server 成功读取目前更新当前值和展示缓存，不向 SQLite 追加历史。高频菜单栏刷新不能回填已经缺失的日期。
- 首页 DTO、日循环和缓存校验仍限定七日。不能把现有窗口参数简单改成 60，也不能扩大启动缓存。
- `limitID` 是额度来源，不是账户身份。首版只能称“该来源已索引的历史”，不能保证全部记录来自同一个登录账号。
- `resetsAt` 是报告的下次重置时刻，不是历史事件日志。官方字段说明见 [Codex App Server — Rate limits](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。
- 删除派生索引也会清除本版历史；源记录仍存在时可随正常索引恢复，已不存在的源记录不能保证恢复。UI 帮助明确说明这一点，不增加第二个清除按钮。

公开规划、测试、截图使用合成数据，不复制真实会话、来源路径、账号信息或能力正文。本机只读诊断结果不作为公共 fixture。

## 3. 产品与交互契约

### 3.1 入口、来源与返回

- 保持七个一级导航和首页三个模块，新增入口是额度模块的次级文字按钮，不挤占全局刷新。
- Sheet 固定打开时首页选定的 canonical source key，并常显来源名称。首版不增加来源选择器；更换来源需关闭并使用首页已有控件。
- 来源是计算边界；禁止以相同名称、空 ID 或未知旧格式把记录并入当前 Codex 来源。当前来源没有历史时显示成功空状态。
- 打开后来源暂不可用，仍保留本次已读历史和来源说明，不自动切到另一个来源。再次打开按当时首页选择读取。
- 关闭按钮和 Escape 返回首页，保留首页滚动位置，恢复入口的键盘及辅助功能焦点。菜单展开时优先由菜单处理 Escape。
- 不再打开第二个 Sheet；每次只展开一个日期。图表选中日与记录行保持一致，键盘和读屏可从按日记录完成等价操作。

### 3.2 信息顺序

1. 当前剩余与“账户报告的下次重置”，周／五小时独立判断有效性；显示当前值自身的采集时间。
2. 近 7／30／60 天控件、只读来源名称。
3. “有记录 X／N 天，可计算 Y／N 天”、历史最后观察时间及读取截至时间。
4. 每日周额度使用趋势、周期切换标记及按日记录。
5. 选中日期的观察起止、基线摘要、已观察增量或不可计算原因、报告重置和已确认切换区间。

单日说明不展开全部原始采样记录，不加载会话正文；仅显示完成判定所需的固定数值和时间摘要。多个切换可以先显示数量，详细区间在本次投影的内存结果中按 20 条分页，保留总数与数据库 identity，不新增分页 SQL，禁止静默截断后宣称完整。

覆盖摘要旁提供可由键盘和读屏访问的帮助：“历史按额度来源汇总，无法区分曾切换的账户。”不显示任何账户标识。

### 3.3 周期与会话状态

- 时间范围为当前时区今天及前 6／29／59 个自然日，截至本次 `asOf`，不是固定 24 小时乘数；未来记录不计入。
- 新增独立偏好键 `com.peiweitang.CodexDirector.quotaHistory.period`，仅保存 `7d`／`30d`／`60d`。缺失或非法值回退 30 天，初始化不写偏好。
- 偏好 App 级共享，跨窗口和重启恢复；不与首页排行、能力清单或文件夹调用周期联动。测试和验证 Host 仅用内存或注入存储。
- 来源、展开日期、焦点和滚动位置由各窗口会话持有；日期超出当前范围时不展示展开内容，返回包含该日的范围可恢复。换来源关闭旧的单日说明。
- 三个范围共享同一 60 日结果；切换不查 SQLite、不读账户、不触发刷新或索引。

### 3.4 状态语义

| 状态 | 展示与恢复 |
| --- | --- |
| 数据库尚未就绪／首次读取 | 历史区原生 loading，计数 `—`；可关闭和切换周期，不误报无记录 |
| 成功且没有记录 | 明确“该来源在此范围尚无额度记录”，不是读取失败 |
| 有记录但不可计算 | 保留日期并显示具体原因，不当作空目录或 0 |
| 部分日期可计算 | 保留可用值，分别列出观测与可计算天数，不称完整覆盖 |
| 已确认零增量 | 显示 0%；不能从单条非零快照推导 0 |
| 今日 | 明确“截至最后观察的部分值”，不是全天最终消耗 |
| 读取失败且有旧结果 | 保留同 key 旧结果，标记未更新并提供本地读取重试 |
| 首次读取失败 | 不可用＋重试，不同时显示“没有记录” |
| 当前值过期 | 当前值等待新报告；已验证历史继续显示，不假定剩余恢复 100% |
| 清除派生索引／epoch 变化 | 立即使旧结果失效；不得在删除后重发旧任务结果 |

“有记录”只表示当天至少一条有效观察；“可计算”也不是完整观测证明。帮助文案说明期间未观察到的使用可能缺失。

## 4. 数据契约与算法

### 4.1 新增接口建议

| 类型／接口 | 职责 |
| --- | --- |
| `QuotaHistoryPeriod` | 7／30／60 天与偏好解析，不复用能力排行枚举 |
| `QuotaHistoryQuery` | 固定来源、`asOf`、时区及固定 60 日计算上下文 |
| `QuotaHistorySnapshot` | 数据库 identity、算法版本、上下文、每日结果、覆盖摘要、观察／索引／读取时间 |
| `QuotaHistoryDay` | 日期、观察数量、结果状态、可选已观察百分点、紧凑基线及起止摘要 |
| `QuotaHistoryDayState` | available、noObservation、missingBaseline、crossDayGap、ambiguousCycle、evidenceConflict；后者不计入可计算天数 |
| `QuotaHistoryTransition` | 前后观察时间、接受的周期 anchor、显示区间；不伪造平台 cycle ID |
| `QuotaHistoryComparisonKey` | 数据库 identity、canonical source、时区、自然日及有效观察截止（含边界类型）；用于首页／详情一致性核对 |
| `DatabaseStore.fetchQuotaHistory(query:cancellation:)` | 一次一致读快照内的有界查询和后台投影 |
| `QuotaHistoryPreferences` | 生产、纯内存、注入式构造，保存独立周期 |
| `QuotaHistoryController` | 单任务生命周期、版本防护、结果切片及窗口状态；主线程不执行 SQL 或全量分类 |

DTO 不持有原始会话、凭证、路径或全量采样数组。界面以最多 60 个日结果及按需分页的切换元数据为输入，不为每个日期重复查询。

### 4.2 查询与有界性

- 只读取选定来源的 `window_minutes = 10080`、60 自然日范围内记录及边界前最后一条前驱；同时间戳按稳定 ID 确定顺序。
- 从现有只读 DatabaseStore actor 开始，使用读快照、现有取消 token 和 5 秒 deadline；不在 SwiftUI `body` 中查询或重建统计。
- SQL 和 Swift 聚合同时受取消约束；总超时覆盖完整请求，不能只限制 SQL 后在主线程长时间计算。
- 一次读取、一次排序和状态分类，分日聚合；不能对 60 个日期逐次重排全部前缀。
- 数据量超出安全处理能力时明确失败并保留旧结果，不按任意行数静默截取后返回成功。先通过性能验证确定是否需要优化查询，不预先新增索引或 schema migration。

### 4.3 消耗、重置与恢复

- 每日值是同来源周额度报告比例的**已观察百分点增量**，不是 Token、费用或全天精确账单。
- 保留 1.6.3 的固定 reset anchor、5 分钟漂移容差、退休周期过滤、自然／提前重置证明和最多 15 分钟窄 lookahead。漂移、低值回放或日历到期本身不生成重置。
- 无可信前驱且第一条非零时，首日未知；跨缺测日不把跨日增量归给某一天。原始比例非法时不得夹成合法零／满额。
- 真实可证明的同日多次周期切换可能令日增量超过 100 个百分点；不为了图表好看钳制数值。
- 分类遇矛盾进入未知段，保留最后可信 anchor 和退休集合，不能看到下一条普通记录就重建基线。
- 详情仅在原有判据证明后继周期时恢复；或“明确零值＋有效未来 reset”，再由同 anchor 非下降观察确认新基线。“恢复当日”取后继周期得到证明或零值基线获得确认的日期，而非较早零值首次出现日。矛盾日至恢复当日仍未知，之后仍需相邻自然日有效前驱；不补算未知旧段，零值恢复不制造重置事件。
- 首页继续使用原七日 fail-closed 包装；抽取共享 `QuotaCycleClassifier` 只能等价迁移原逻辑，新恢复语义限定在历史详情，使用独立历史算法版本。
- 详情三种范围从同一上下文切片，同源同日的数值、原因与标记不得因范围切换而变。
- 首页与详情上下文不同，允许一方未知；**具备相同 comparison key 时，两者若都显示确定值则必须相同**。已结束日以次日零点为排他上界，当日以 `asOf` 为包含上界；边界由同一时区的 Calendar 生成。数据库 identity 相同但截止／时区不同，不构成算法冲突，先分别表达统计时间；数据库版本变化则标旧并重读。比较资格一致且数值不一致时，详情降级为 `evidenceConflict`，排除出可计算天数，不覆盖首页或展示两个相互矛盾的确定值。
- 周期切换只称“在 A—B 两次观察之间确认”；`resetsAt` 单独称报告的重置时间，不显示精确实际发生时间。单日不可计算与有证据的周期切换可同时存在。

### 4.4 刷新、并发与兼容

- 历史打开、切范围、选日期和重试均不触发源扫描或 app-server 读取；当前值只接收既有共享模型的更新。
- 索引成功提交时，合并一次历史失效／重读；实时账户更新只改当前值，不让历史时间看似变新，也不触发历史查询。
- controller 只有一个进行中任务。关闭、换来源、删除索引或新请求取消旧任务；发布前核对 source/query key、task generation、数据库 epoch/dataGeneration。
- 午夜／时区变化使上下文过期；可见详情合并一次本地重读，隐藏时不轮询，恢复可见时再检查。
- 多窗口保留独立结果与浏览状态，不建立各自的索引器或账户进程。相同 key 的并发读取可沿现有读服务合并；不能因此扩大 AppModel 全局高频发布。
- SQLite schema、rollout parser version、presentation cache schema v1、首页 `dailyUsageAlgorithmVersion` 及 `.codexpack.zip` manifest v1 均保持不变。

## 7. 验收与性能门

### 功能与正确性

- 近 7／30／60 自然日、DST／时区／午夜边界和记忆偏好正确；范围切片同源同日一致。
- 多来源隔离、未知来源不合并、五小时不生成周历史；没有当前值不等于历史为空。
- reset 漂移、旧周期回放、自然／提前重置、缺测、缺基线、矛盾恢复和多次真实切换均有合成回归。
- 旧首页七日、菜单栏当前值、刷新调度、1.6.3 缓存防回写、文件夹成员、评价及 manifest v1 不回归。
- 空结果不报故障，故障不报空结果，已观察零不与未知混同；三类时间不互相替代。
- 删除索引／取消／超时后旧结果不能回填；反复开关 Sheet 不遗留任务或持续计时器。

### 性能目标（尚未实测，不是当前通过结果）

合成基线：全库 100 万条额度记录，选定来源近 60 日 10 万条，包含多个来源、缺测、重置、相同时间戳与真实长度字符串 ID。Release 冷／暖各至少 20 次，记录硬件、数据量、工具、构建、median／p95／max。

- 入口／周期操作的即时 UI 反馈 p95 ≤100ms。
- 首次按需读取＋聚合端到端 p95 ≤1s、最大 ≤2s；超过目标需优化或显式复审，不能宣称达标。
- 取消响应目标 ≤250ms；请求总 deadline 5s，超时保留旧内容且可重试。
- 固定结果的周期切换：零 SQL、零源扫描、零账户读取，且不重新分类。
- 首页缓存启动及原七日额度性能不退化；历史未打开时零新增历史查询和轮询。
- 若目标数据下内存或查询不达标，先做查询计划／单次聚合修正；增加索引、持久聚合或扩大缓存需回到架构评审，不静默扩大范围。

### 界面与无障碍

中／英文 × Light／Dark，720×480、1280×800及宽窗口；键盘、完整热区、Escape、焦点恢复、长日期、Increase Contrast、Reduce Motion／Transparency。真实 VoiceOver 与 AX 证据分别记录；未经用户允许不修改系统设置，未验证项如实列出。

## 8. 后续阶段与回退
