# Codex Director 侧栏切换性能优化实施计划

> 后续实施按 executing-plans 工作流逐步验证。

目标是缩短侧栏点击后的高亮反馈和页面出现时间，优先处理自定义 Agent 和自定义 Skill 列表。

从现有 NavigationSplitView 和原生 List 开始。先补齐八个页面的测量，再分别优化导航反馈、重列表重新进入和设置诊断。每个改动单独测量，便于判断收益和回退。

使用 SwiftUI、AppKit、项目现有 Release 性能验证程序、XCTest 和合成数据。

## 已有基线

2026-11-06 在同一台 Mac 上，以 1280×800 窗口和 283 个合成能力运行两个版本。以下数据来自每版 19 次重复进入，计时从应用切换状态到布局稳定。真实点击到首帧待测，额度历史已有独立探针，需要并入统一记录。

| 页面 | 图表更新前 p95 | 当前 p95 |
| --- | ---: | ---: |
| 自定义 Skill | 596 ms | 596 ms |
| 自定义 Agent | 524 ms | 484 ms |
| 安装 Skill | 193 ms | 190 ms |
| 设置 | 198 ms | 185 ms |
| 首页 | 157 ms | 119 ms |
| 安装插件 | 115 ms | 104 ms |
| 能力文件夹 | 85 ms | 87 ms |

当前版的侧栏状态写入 p95 低于 0.1 ms。每次返回自定义 Agent 和 Skill 时，分别发生 132 和 426 次行视图构建调用。两个列表的数据库身份校验通常低于 1 ms，19 次暖切换分别只读了 19 次身份，没有完整清单查询。设置的 19 次进入均读了诊断。先前的 AppKit 试验在大列表中有收益，也曾拖慢较小列表，视觉与无障碍验收尚未完成。见 [历史测量与试验](../PERFORMANCE.md)。

## 执行步骤

### 1. 固定基线，测清点击到首帧

- 使用 `Sources/CodexDirectorApp/InteractionPerformanceHost.swift` 和 `Sources/DirectorUI/Validation/InteractionPerformanceDriver.swift`。复用额度历史的首绘制探针，将八个入口纳入同一次序列，单独记录本地鼠标或键盘输入、侧栏目标高亮、正确页面首帧、布局稳定和页面任务。保留 AppKit 绘制标记与屏幕可见帧的测量区别。自动化命令提交时间单列。
- 同一 Mac、同一组数据、同一窗口宽度、同一外观。每个视口运行一次首次进入和至少 30 次暖切换，另用录屏或等效可核对的呈现记录验证真实输入。重复比较时交换基线和候选版运行顺序，避免编译和其他测试并行。检查正常节奏与快速切换。
- 更新 `Tests/DirectorUITests/InteractionPerformanceTests.swift` 和 `scripts/validate-interaction-performance-report.sh` 中受八入口事件变更影响的契约。运行 `swift test --filter InteractionPerformanceTests`，再用同一合成 Release 包分别执行 `./scripts/run-interaction-performance.sh --reuse-build <build-root> --fixture interactionRepresentative --samples 31 --width 1280 --height 800` 和 720×480 版本。
- 记录每页 p50、p95、最大值、布局耗时、行视图构建次数、数据库查询类型与次数。用 1,000 项压力数据再测自定义 Agent 和 Skill。性能记录只保留合成数据的汇总信息。

### 2. 让侧栏先给反馈

- 在 `Sources/DirectorUI/AppShell/DirectorRootView.swift` 用诊断数据判断选中行绘制是否被新内容布局拖后。若存在，隔离选中样式与重内容切换的更新范围。保留现有原生侧栏的焦点和可访问选中语义。
- 快速 A → B → C 时，以最新选择驱动显示和进入任务。若需要分阶段显示，先绘制真实选中状态和对应页面外壳，再处理重列表。避免用固定延迟或把占位内容当作完成来满足指标。
- 复测鼠标、方向键、从首页进入详情和快速往返，核对旧页面的任务或晚到结果不会影响新页面。

### 3. 减少 Agent 和 Skill 列表重复布局

- 在 `Sources/DirectorUI/Capabilities/CapabilityLibraryView.swift` 区分行视图构建、原生 List 布局和根视图更新。保留原生 List，先去掉测到的重复布局和无关重算，尽量复用已有稳定行输入。只在完整首帧和可交互性都提升时保留候选改动。
- 如果原生 List 的重复挂载仍占主要开销，仅对两个自定义清单试验窗口内的有界视图复用。首次进入时按需创建，最多保留两个，离开后停止页面任务并从键盘和辅助功能焦点路径移除。窗口关闭释放保留视图。若保留视图无法安全停止后台工作、恢复状态或限制内存，撤回该候选。
- 核对既有搜索、筛选、排序、滚动、详情及项目归属语义。沿用数据库身份与分类版本校验。刷新、切换项目和清空派生数据后，旧视图或晚到结果不能作为当前数据发布。用 `Tests/DirectorUITests/CapabilityLibraryStateTests.swift` 和 `Tests/DirectorUITests/CapabilityLibraryPresentationTests.swift` 回归验证。
- 两种候选都过不了指标时，以现有 AppKit 原型单独验证冷进入和大列表收益。采用新渲染器前需通过视觉、焦点、键盘和实际 VoiceOver 验收，并单独决策适用页面。

### 4. 去掉设置的重复诊断查询

- 在 `Sources/DirectorUI/DataStatus/SettingsView.swift` 与 `Sources/DirectorUI/AppShell/DirectorAppModel.swift` 将诊断重新读取的条件与可靠的数据版本失效信号关联。首次打开加载一次。同版本再次进入复用诊断数据。索引更新、删除重建以及失败后重试时仍需正确刷新。
- 若现有信号无法覆盖所有写入路径，先保留轻量身份确认，再以确认结果决定是否读取统计。验证快速离开重进、同版本重复进入及版本变化后的查询次数和结果。
- 能力文件夹在缓存缺失时才补读使用数据。本轮把它纳入回归测量，额外优化需由独立的耗时证据触发。

## 验收与安装

- 鼠标和键盘输入到侧栏选中反馈 p95 ≤ 100 ms。合成代表样本中，两个自定义清单的重复进入到首个正确可用内容 p95 ≤ 250 ms。压力样本对应目标 ≤ 500 ms。首入单列，保留首次建立列表的真实成本。布局稳定耗时单独对比。
- 八个入口都参加回归。以同条件重复对照验证首次进入和暖切换。其余页面 p95 若超过基线的 10% 或 15 ms 中的较大值，先交换顺序复测。可复现的退化阻止候选安装。若采用视图复用，同一窗口的稳定期驻留内存以基线的 115% 为上限，连续往返后不得持续增长。
- 暖切换不触发源索引、账户读取或完整清单查询。列表可保留现有一次轻量身份校验。同一有效数据版本下重复打开设置不再读诊断统计。使用合成数据验证后台刷新、丢失缓存及失效后的正确性。
- 通过 `./scripts/verify.sh`、`./scripts/build-local-app.sh` 和安装包校验。按 [.design/codex-director/VALIDATION_PLAN.md](../../.design/codex-director/VALIDATION_PLAN.md) 核对焦点、键盘和无障碍。首帧测量或关键交互验收缺失时记录为待验。通过相应验收后按项目约定保留旧包、覆盖安装并在本机复核切换。

## 实施记录

保留设置诊断复用和能力清单任务去重。设置在索引元数据变化后重新读取诊断，结果返回后再次确认当前数据库版本。能力清单由页面任务统一读取，切换范围时取消旧任务。合成环境测得设置首次读取一次诊断，30 次同版本重进均只核对元数据。四个能力清单的暖切换各保留一次身份校验。

Release 测试包对八个入口分别记录应用内的侧栏绘制、目标绘制和布局稳定。下表为首次进入之后 30 次切换的目标绘制 p95。完整报告另记首次、p50、最大值、行构建和查询次数。

| 场景 | 自定义 Agent | 自定义 Skill |
| --- | ---: | ---: |
| 宽窗口基线 | 617 ms | 706 ms |
| 宽窗口平铺原生列表 | 515 ms | 578 ms |
| 宽窗口按需构建行 | 564 ms | 647 ms |
| 宽窗口反序基线 | 560 ms | 596 ms |
| 窄窗口基线 | 399 ms | 431 ms |
| 窄窗口平铺原生列表 | 348 ms | 388 ms |
| 窄窗口按需构建行 | 365 ms | 376 ms |
| 1,000 项压力数据按需构建行 | 549 ms | 570 ms |

保留两张重页面的试验拖慢了首页、设置等其他入口，已撤回。平铺列表的行构建仍为 198 和 426 次。按需构建把宽窗口中的两项都减至 28 次，窄窗口减至 16 次。反序宽窗口对照显示 Skill 的绘制 p95 从 596 ms 升至 647 ms，因此撤回列表渲染试验。AppKit 渲染仍限于诊断模式。

在中文深色合成窗口验证了鼠标切换、方向键切换、打开详情、Escape 恢复列表焦点、分组折叠及额度历史。三次原生事件记录只覆盖 AppKit 绘制标记，样本不足以报告输入延迟 p95。实际 VoiceOver、屏幕呈现测量和性能验收仍待通过。独立质量复核结论为阻断安装。

AppKit 原型在首次试跑时缺少独立托管视图所需的语言环境。修正后完成 1,000 项数据的宽窗口试跑。两个清单的首次绘制为 532 ms 和 446 ms，之后各五次绘制的中位数为 335 ms 和 350 ms。这个样本量只用于判断方向。应用包继续使用既有原生 List。

完整验证报告 1,378 项测试，4 项跳过，零失败。公开审计与正式 Release 包的应用身份、双架构、签名校验均通过。独立性能验收仍阻断覆盖安装。

### 同构建轻页面对照

在同一个签名的合成 Release 包中运行完整列表和轻页面。两组均使用 1280×800 窗口和 283 项代表数据。轻页面保留相同的侧栏、选中状态和窗口结构，只替换自定义 Agent 与自定义 Skill 的右侧内容。每组先进入一次，再按相同顺序完成 8 次方向键和 8 次鼠标暖切换。每次都检查侧栏实际选中项。

| 输入与目标 | 完整列表高亮中位数 | 轻页面高亮中位数 |
| --- | ---: | ---: |
| 方向键，自定义 Agent | 621 ms | 48 ms |
| 方向键，自定义 Skill | 619 ms | 52 ms |
| 鼠标，自定义 Agent | 648 ms | 51 ms |
| 鼠标，自定义 Skill | 637 ms | 51 ms |

每格 4 次暖切换，时间从原生输入事件到应用内绘制标记。完整列表的侧栏高亮中位数与内容绘制中位数只差约 8–9 ms。轻页面对照和主线程调用栈均支持右侧布局推迟侧栏反馈。Instruments 没有记录到可用的 SwiftUI 事件，调用栈来自对隔离合成进程的单独采样。录屏权限预检未通过，屏幕呈现时间和发布 p95 另行验收。

### 搜索焦点与真实内容加载

在 AppKit 候选中，搜索框位于不可选中的表头行。允许该行的可编辑控件取得焦点后，首次输入成功，刷新仍会替换表头并丢失编辑器。搜索改为只更新结果行，保留正在编辑的表头。宽窗口中文深色合成数据中，用鼠标点击搜索，再连续按键缩小结果范围，Agent 与 Skill 均保持焦点并显示正确条目。清空 Agent 查询恢复原列表，切到设置后旧编辑器不再接收输入。

固定单元格尺寸的试跑将两页真实内容的应用内绘制最慢值从 283 / 325 ms 降至 267 / 273 ms。原生绘制后挂载并使用单元格边界自动缩放的组合，8 次暖切换中侧栏最大值为 61 / 66 ms，真实内容最大值为 252 / 265 ms。小样本用于选择候选。后续候选还按视口宽度初始化表格并合并首次行加载。

### 单滚动容器对照

AppKit 表格按视口宽度初始化的候选在 30 次宽窗口暖切换中，两个列表内容绘制 p95 为 280 / 285 ms，侧栏绘制 p95 为 69 / 77 ms。千项压力样本的内容绘制 p95 为 349 / 365 ms。窄窗口再次验证了连续搜索，并滚动至正确的实际结果。

把两个自定义清单改为一张按需构建的 SwiftUI 滚动视图，仍使用原生侧栏及原有标题、筛选、统计和行样式。每组均包含首次进入和 30 次暖切换，八个入口每次暖切换都有两项应用内绘制标记。

| 样本 | Agent 侧栏 / 内容 p95 | Skill 侧栏 / 内容 p95 |
| --- | ---: | ---: |
| 1280×800，代表数据 | 71 / 194 ms | 75 / 205 ms |
| 720×480，代表数据 | 71 / 141 ms | 65 / 135 ms |
| 1280×800，千项数据 | 67 / 188 ms | 76 / 197 ms |

宽窗口合成数据用实际输入验证两个清单的连续搜索、正确结果和焦点保持，也验证了通过辅助功能操作打开对应 Agent 详情。详情尚未获得可靠键盘焦点时，Escape 存在未关闭的情况。以上分布来自交互补丁前的诊断包。方向键、详情焦点返回、文件夹菜单、完整无障碍和生产启用仍需用最终候选验证。


### 正式路径候选复验

正式构建只在自定义 Agent 和自定义 Skill 两页启用按需构建。侧栏保留原生选中行为；先反馈选中状态，再挂载真实结果。其他入口保持原有渲染路径。正式 Release 和合成诊断包都使用这一默认路径，旧渲染只可在诊断构建中显式切回。

中文深色的最终合成窗口验证了真实点击、连续输入、正确匹配、清空及焦点保持。列表中方向键能进入下一个条目，Return 打开对应详情，Escape 关闭并回到原条目；详情打开期间按方向键不会改变返回目标。独立文件夹菜单的操作在合成候选中通过。详情关闭按钮出现在辅助功能树，当前系统没有开启完整键盘导航，未确认 Tab、Shift-Tab 和初始焦点是否进入该按钮。未修改系统设置，也未将辅助功能树检查视为实际 VoiceOver 验收。

完整验证共报告 1,378 项测试，4 项跳过，零失败；最后的详情焦点调整再通过了 66 项定向测试。公开隐私审计通过；正式 Release 构建为 1.7.2 (48)，arm64 和 x86_64，ad-hoc 签名校验通过。

在英文浅色 720×480 合成窗口也通过两个列表的连续键入、焦点保持和滚动后的真实结果核对。每组正式性能样本含首次进入和 30 次暖切换。八个入口每次暖切换都有侧栏和内容绘制标记；两个列表的完成标记对应已装入的真实内容，未计入占位。窄窗口的结果可滚动到达。两个列表重复进入每次只核对一次数据版本，无完整清单查询、源索引或账户读取。

| 场景 | Agent 侧栏 / 内容 p95 | Skill 侧栏 / 内容 p95 |
| --- | ---: | ---: |
| 1280×800，代表数据 | 70.9 / 191.6 ms | 72.6 / 190.7 ms |
| 720×480，代表数据 | 78.4 / 158.1 ms | 64.0 / 134.0 ms |
| 1280×800，千项数据 | 64.1 / 175.7 ms | 69.0 / 188.0 ms |

在同条件的原生 List 基线下，其他六个入口的暖切换侧栏和内容 p95 均未超过计划定义的退化阈值。以上时间以应用内绘制标记为终点，不是从实际按键或点击到屏幕可见像素的计时。独立验收仍需区分应用绘制已达标与真实呈现、完整键盘焦点和实际 VoiceOver 未验证。

最终独立质量验收通过，允许本地覆盖安装。旧版已保留在废纸篓；安装包与通过验收的正式产物逐文件及可执行文件 SHA-256 一致。重启正式应用后，再次核对两个侧栏入口、连续输入、焦点保持和清空恢复。系统设置未修改，真实 VoiceOver、完整 Tab 焦点和屏幕呈现延迟仍单列为未验证。
