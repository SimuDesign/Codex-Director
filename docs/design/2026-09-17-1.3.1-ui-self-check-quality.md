# 1.3.1 UI self-check verification

Date: 2026-09-17  
Target: macOS 26+, `1.3.1` / internal build `26`  
Status: independent local-patch acceptance passed; recoverable deployment and installed runtime checks passed.

## Scope and preservation

UI Designer supplied the bounded contract, Frontend Developer implemented
the presentation repair, and a separate Quality Engineer performed read-only
acceptance. Root owns build verification and the recoverable local installation.
The existing Scheme A visual Skill governed the page grid, opaque surfaces,
brand-outline choices, native controls and evidence requirements.

Changes are limited to DirectorUI presentation, its tests, version sources
and documentation. DirectorCore, application data wiring, index/parser
versions, relation resolution, preference contracts and package manifest v1
are unchanged. Saved Self Training and other folder memberships are not
cleared, seeded or rewritten. No GitHub push, Tag or Release is part of this
repair.

## Findings and repairs

- Native List Section headers did not share ordinary-row gutters. Structural
  headers now use the same content grid as folder cards and result stages.
- Independent rows lacked explicit vertical rhythm. Each adjacent block has
  one named gap owner, without duplicated padding.
- System-blue segmented fill was replaced by a locally owned, real
  NSSegmentedControl with native selection/action/AX and brand-outline paint.
  Control labels retain 13pt type and equal-height compact wrapping.
- Native Menu label synthesis discarded label-local paint and dimensions.
  The actual Menu now owns an outer 36pt sort field or 28pt icon-menu frame.
- Independent native testing caught short Settings labels wrapping at natural
  width. Intrinsic measurement now matches semibold painting, rounds upward
  and adds the existing 4pt tolerance; explicit narrow proposals remain narrow.
- Independent AX testing caught inaccessible structural-row actions. Child
  containment alone did not restore native action children in the running
  List, despite passing source contracts. Real NSButton attempts also failed
  at that container boundary. Product Designer reviewed and root approved a
  local nonselection ScrollView/lazy-content exception, documented before
  frontend implementation. The four restored SwiftUI actions now export as
  genuine individual native Buttons and perform New Folder, Back, header Add
  and empty-state Add through actual AX activation. Cancel leaves synthetic
  memberships unchanged. Native entry/interior headings and all three
  selected-state radio choices are individually exposed.
- A DEBUG validation-host Escape handler consumed dismissal even with a nil
  closure. Its modifier is now completely absent outside capture mode.
  Actual normal-host Escape closes Skill detail and preserves its parent
  folder/expanded relationship; production SideSheet behavior was not changed.

## Native evidence and dimensions

Only synthetic validation fixtures were used. User screenshots and production
content were not copied into the repository. Native Save PNG captures exclude
the desktop and use the isolated validation host.

The standard host preset measured a `1280×742pt` product viewport, including
a `228pt` sidebar. Its captured module was `2104×1484px` at 2×, or
`1052×742pt`; neither the nominal preset nor a downscaled live screenshot is
reported as the actual content viewport.

The fresh ScrollView painted-bound check measured a `40pt` common leading gutter,
`16pt` tabs-to-search and search-to-stage gaps, a `36pt` search/sort height,
and approximately `12pt` horizontal search/sort separation. Fresh entry
section headings and both grids share that gutter. These are native synthetic
captures of the new container, not reused List samples.

Fresh compact zh/Dark and en/Light checks used the `720×480pt` product
preset. The saved module PNG measured `984×908px`, or `492×454pt` at 2×;
it is not labeled as a full 480pt-high module. Painted gutters were `16pt`,
search and sort were `36pt`, stacked search-to-sort gap was `8pt`, and the
stage gap was `16pt`. Wrapped English tab labels retained equal segment
heights and readable text. Wide en/Light used a `1600×742pt` product and a
`2744×1484px` module (`1372×742pt`); its 1280pt measure was centered with
`46pt` side margins and uncut far-edge controls.

Long-content testing caught and closed a per-tab scroll restoration defect.
An outer primary target layout disabled nested resource targets; sibling
header/grid/resource target layouts, explicit top anchoring and
context-captured callbacks now preserve meaningful view IDs. The final native
round trip restored the same previously visible Agent and Skill, not the
first row or grouped stage. Partial rows become top-aligned, so fractional
scrollbar values need not be identical: Agent `1 → 0.946050` retained Agent 4,
and Skill `0.337426 → 0.313324` retained Skill 5.

The short entry fixture could not establish a distinct folder-row target.
Eight explicitly approved synthetic folders were therefore created through
the pure-memory host UI only. Entry `0.388979 → 0.356209` retained the same
QEScroll 6 row after opening QEScroll 5 and returning. New contexts started
at their own header; no production folders or members were added. All four
native structural actions were rechecked on the final package at compact
width. Final CLI gates and the independent outcome passed below.

## Explicit limits

The validation host reports actual system accessibility settings; it does not
simulate them. Actual OS Increase Contrast, Reduce Motion, Reduce Transparency
and VoiceOver speech were not exercised, and no global settings were changed.
Global Keyboard Navigation traversal is not claimed: current system defaults
limit Tab traversal, and changing them was outside this task. Native AX
activation, pointer actions and search-editor key behavior are separate evidence,
not substitutes for actual VoiceOver speech or full keyboard traversal.

Pending/failure/Retry branches have source and unit-contract coverage only;
the host does not inject these states for native interaction. The DEBUG-only
capture toggle can reset the synthetic folder browsing state and requires
native content focus for its Escape handler. Normal-host Save PNG captures
were used for the folder evidence; normal production-detail Escape passed
separately. This validation-utility limitation is not a production keyboard
repair or a claim of capture-toggle state preservation.

This is a proportionate local UI patch acceptance, not a declaration that the
complete formal-release accessibility matrix has been certified.
