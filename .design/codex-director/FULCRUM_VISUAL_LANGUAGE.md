# Fulcrum 视觉语言研究与 Codex Director 转译规范

状态：参考研究完成；作为后续 UI 方向与视觉验收的约束文档，不是生产实现规格。  
研究日期：2026-08-31  
主要参考：[Fulcrum Rocks](https://fulcrum.rocks/?ref=landings)  
适用范围：Codex Director 原生 macOS 主窗口的视觉方向、首页构图、图表、图标和内容区段。  

## 1. 为什么不应先做黑白稿

先做黑白稿并不是普遍错误，但不适合这次任务。

黑白线框适合验证导航、信息架构、字段完整性和操作路径。用户此次不满意的并不是首页缺少字段或路径，而是视觉品质、构图辨识度、图表工艺和品牌感不足。Fulcrum 的关键价值恰好来自以下元素的同时作用：

- 大面积蓝—冰蓝—薄荷光场参与版面配重，而不是最后叠加的“皮肤”；
- 超大标题与强制换行决定区段轮廓；
- 专属线稿、案例图像、拼贴和认证轨道构成视觉锚点；
- 开放画布、横向轨道、三列卡片、中心式陈述和数据舞台交替出现；
- 不对称圆角、细描边、导航悬浮条和填充式主按钮共同决定材质感。

删除颜色、材质、图像和排版尺度后，参考中最重要的构图信息也被删除。结果只能验证“内容是否都在”，不能验证“设计是否成立”。因此后续采用以下规则：

1. 纯功能新流程可以先做低保真线框。
2. 已有功能的高审美视觉重构，直接从全彩高保真构图开始。
3. 黑白稿只可作为局部信息校验材料，不得作为 Fulcrum 方向的视觉审批稿。
4. 高保真稿必须同时包含真实文案密度、真实图表轮廓、视觉锚点和目标窗口比例。

## 2. 研究方法与覆盖范围

本研究以公开网站当前线上版本为主，结合用户此前提供的纵向整页截图判断节奏。没有复制网页图片、字体文件、SVG、代码或品牌资产。

实际检查覆盖：

- 桌面宽度 1512 pt 的完整页面与关键中段；
- 768 pt 中等宽度；
- 414 pt 窄屏；
- 首屏、服务轨道、案例轨道、行业区、AI 服务区、UI 拼贴区、流程区、认证区、指标区、证言区和联系区；
- 实际字体声明、正文与标题计算样式、主按钮渐变、圆角、描边、脚本与动效库；
- 横向内容轨道、固定导航、响应式折叠和移动端重排。

限制：

- 本文只记录公开页面可观察到的视觉和交互事实，不推断设计团队的内部品牌策略。
- 没有复刻原站全部时间轴，因此运动章节描述的是已确认的技术与可见行为，不是逐帧动效规格。
- 网站当前线上内容与用户早期提供的 Fulcrum 长截图存在版本差异；本文以当前线上版本为事实源，同时保留两版共同的视觉 DNA。

## 3. 一句话视觉命题

**Fulcrum 不是“黑底青色卡片站”，而是一个以超大中性无衬线文字为骨架、以冷色光场和专属技术图像为空间材料、通过不断切换区段构图来维持节奏的深色编辑式长页。**

Codex Director 应学习的是这种构图机制、尺度反差、区段变化和视觉锚点，不是复制其营销文案、品牌图形或网页导航。

## 4. 线上页面解剖

当前页面由 11 个编号区段组成，编号从 `/01` 到 `/11`。每个区段保留同一字体、色彩和细线体系，但采用不同的内容结构。

| 区段 | 线上角色 | 主要构图机制 | 对阅读节奏的作用 |
| --- | --- | --- | --- |
| `/01` | 品牌首屏 | 超大双色标题、左下说明与 CTA、右侧复古电脑线稿、满幅蓝色光场 | 先建立品牌世界与视觉尺度 |
| `/02` | 服务范围 | 左侧巨型两色陈述、右侧短说明、下方横向服务卡轨道 | 从开放舞台进入可浏览内容 |
| `/03` | 项目案例 | 大数字标题与说明、图像案例卡横向轨道 | 用真实图像提高信息密度与可信度 |
| `/04` | 行业 | 左侧大标题与定制线稿、右侧分组文字 | 从卡片切换为插画 + 索引式说明 |
| `/05` | AI 服务 | 超大两色标题、三张高卡片 | 用强对比陈述后回到规则网格 |
| `/06` | UI 能力 | 居中标题与说明、四周悬浮项目图像拼贴 | 通过非网格构图制造中段峰值 |
| `/07` | 协作流程 | 左标题、右说明、四列带小图标步骤 | 将节奏收紧为轻量说明带 |
| `/08` | 合规 | 中心标题，认证标志围绕分布，强光场 | 用环绕式构图制造第二个视觉峰值 |
| `/09` | 核心指标 | 巨型标题，三组超大数字横跨页面 | 去除卡片，以数据本身形成视觉舞台 |
| `/10` | 客户证言 | 标题与说明，横向高卡片滑轨 | 恢复内容容器但保持水平运动感 |
| `/11` | 联系 | 左侧巨型收束陈述，右侧表单，左下光场 | 以不对称双栏结束，不使用常规页脚堆栈 |

重要规律：**统一来自视觉语言，不来自统一模板。** 区段不共享同一种“标题 + 四张圆角卡片”结构，而是共享字体、光色、描边、节奏和动作语法。

## 5. 视觉 DNA

### 5.1 宏观结构：编辑式长文，而非仪表盘

- 页面以连续长画布组织，区段之间主要靠留白和一条横向细线分隔。
- 不是每个区段都有独立背景或完整卡片边界。
- 标题、说明、图像和卡片在每一段重新编排，形成“开放—密集—开放—密集”的呼吸。
- 视觉峰值并非均匀出现，而是在首屏、UI 拼贴、合规和指标区集中爆发。
- 横向滑轨允许内容超过视口，传达内容仍可继续，而不是压缩成密集小卡片。

### 5.2 排版：尺度反差是第一识别点

线上页面使用 `Neue Montreal` Regular/Medium，正文与标题均为同一中性 grotesque 家族。系统不是靠多字体营造层级，而是靠尺度、行高、字重和颜色分层。

桌面实测示例：

- 主区段标题约 `89.6 px`，行高约 `85.1 px`，略为负字距；
- 卡片大标题约 `46.8–48 px`；
- 数据指标远大于普通标题，以自身成为图形；
- 说明文字保持紧凑，宽度受控，不与大标题争夺层级。

响应式实测：

- 768 pt 时主区段标题约 `52.2 px`；
- 414 pt 时约 `48.4 px`；
- 移动端仍然保留巨大标题，而不是全部缩回普通应用字号。

排版规则：

- 大标题使用短句和人为换行，形成清楚的几何轮廓。
- 关键短语使用蓝—冰蓝—薄荷渐变或分段着色，其余保持近白。
- 辅助说明与正文使用冷灰，不与标题同亮度。
- 区段编号很小，只提供定位，不抢占主层级。
- 没有用大量粗体、徽章或全大写替代真正的字号层级。

### 5.3 色彩：光色体系，而不是单一青色

实测基础色：

- 页面底色：`rgb(5, 5, 5)`，近黑但非蓝灰面板色；
- 主文字：`rgb(233, 238, 241)`，略带冷感的近白；
- 正文：`rgb(145, 153, 158)`，中性冷灰；
- 主按钮：`rgb(13, 153, 255)` → `rgb(153, 250, 244)` 的水平渐变。

色彩使用方式：

- 蓝色、冰蓝和薄荷不是平均铺满所有组件，而是在标题关键字、CTA、图像光场和少数交互点集中出现。
- 深蓝与青绿色光场承担空间配重，经常贴近页面一侧或区段角落，不是每张卡片背后各放一个光晕。
- 黑色区域保留充分，避免页面变成通体蓝色。
- 白色和灰色仍然承担绝大多数信息，可读性优先。
- 语义色与品牌强调色分离；原站评论评分等少量信息使用独立颜色。

### 5.4 光与材质：环境光塑造画布

- 页面不是纯黑平面；低频、宽范围的蓝色和深海青光场贯穿多个区段。
- 光场常常从边缘进入，并在中部退回黑色，形成不对称重心。
- 卡片本身接近黑色，只依靠细灰描边、极轻亮度差和内容图像区分。
- 基本没有依赖大面积投影制造层级。
- 光不是状态反馈；它属于版面环境。按钮、焦点和错误仍需独立状态表达。

### 5.5 卡片：只在内容需要容器时出现

卡片的共同特征：

- 黑色或极深色填充；
- 细描边；
- 尺寸大，内部留白足；
- 角部不是统一胶囊，常见一个角更明显的不对称切角或圆角；
- 小型圆形箭头放在右上角，作为明确的可进入提示；
- 图像卡让图像承担大部分视觉重量，文本只提供识别和类别。

禁止误读：Fulcrum 不是“卡片越多越好”。行业、UI 拼贴、合规、指标和联系区都没有采用相同卡片网格。

### 5.6 图像与插画：每个大区段有专属视觉锚点

参考的精致度很大程度来自定制视觉材料：

- 首屏复古电脑为白色技术线稿，与冷色光场结合；
- 案例区使用真实产品画面而非抽象占位图；
- 行业区有专属医疗设备线稿；
- UI 区使用多个不同尺寸的项目画面围绕中心标题；
- 合规区将认证标志组成轨道，而不是放入普通四列卡片。

这些材料不可直接复制。Codex Director 的等价物应来自自身产品语义：额度周期、资源类型、索引状态、证据链、调用轨迹和能力结构。

### 5.7 图标：少、轻、位置明确

- 图标用于步骤、箭头、导航提示和认证标志，不用于装饰每一行文字。
- 小图标常放在独立深色小方块或小圆形中，留有充分负空间。
- 箭头是反复出现的行为符号，但尺寸克制。
- 图标家族以线性、低细节、统一描边为主；大型视觉锚点则升级为专属线稿插画。

### 5.8 分隔线与边界

- 区段上边界多为低对比度横向细线。
- 细线建立连续页面节奏，避免每段都出现完整背景盒。
- 卡片边界略亮于区段分隔线，用层级差而不是阴影区分。
- 横向滑轨在底部使用细进度线，成为导航与装饰的共同元素。

### 5.9 主按钮

主按钮不是描边按钮：

- 使用蓝至薄荷的完整填充渐变；
- 前景文字为近黑，保证对比；
- 右侧使用一个小圆点或动作符号；
- 圆角并非标准胶囊，实测包裹层约为 `5px 5px 16px` 的不对称圆角；
- 按钮面积充足，通常是区段中唯一高饱和交互元素。

这解释了此前“只用纯青色”或主按钮仍为描边样式为何无法接近参考。

### 5.10 动效与响应式

已确认页面加载：

- GSAP；
- Lottie/bodymovin；
- Swiper；
- Splitting；
- CSS 平滑滚动和大量 `transform`/`opacity` 过渡。

可见交互语法：

- 横向卡片与证言轨道；
- 固定黑色导航条；
- 区段内容随滚动进入；
- 箭头与卡片具备轻量位移/显隐反馈；
- 视觉运动主要服务于进入、轨道浏览和空间连续性。

响应式规律：

- 768 pt 时完整导航折叠为汉堡菜单，主标题与光场仍保持大尺度；
- 414 pt 时首屏改为标题—插画—说明—CTA 的纵向顺序；
- 部分多卡区不强行压成微型多列，而保留横向轨道；
- 窄屏仍保留大标题、强渐变和图像锚点，品牌感没有因响应式而消失。

Codex Director 需要保留 Reduce Motion，且不能把网站滚动叙事原样搬入桌面应用。可转译为短时淡入、选择过渡、图表更新和横向内容提示，不引入持续背景动画。

## 6. 为什么此前方案效果差

### 6.1 把视觉参考降维成色板

此前主要复制了黑色、青色、薄荷和圆角卡片，却没有复制尺度反差、区段变化和专属视觉锚点。于是只得到“换了 Fulcrum 配色的原界面”。

### 6.2 锁死了原有截图轮廓

生成提示同时要求保留当前页面结构，又要求产生明显重构。模型会优先满足可测量的保留项，最终只在边框、颜色、间距和图标上微调。截图的原有几何成为最强约束。

### 6.3 把所有模块都面板化

统一卡片可以提高一致性，但当额度、能力规模和排行都使用相似的圆角面板时，三个模块失去角色区分。Fulcrum 的一致性来自语言，而不是每段重复同一个容器。

### 6.4 缺少专属图表和图像构图

参考网站的大型线稿、项目画面、合规轨道和数据舞台都是专门设计的。此前方案沿用默认环图、默认柱图和 SF Symbol 装饰，画面精致度不会仅靠渐变提升。

### 6.5 黑白稿删除了要评审的内容

黑白稿只证明信息还在，无法证明光色、材质、图像和尺度是否成立。把它当作视觉方向审批稿，导致后续在一个普通骨架上继续精修。

### 6.6 验收偏向合规，不足以判断设计水准

此前验收能检查 token、断点、可访问性和数据语义，但缺少“画面轮廓是否改变”“是否形成专属视觉锚点”“是否存在区段构图变化”的审美硬门槛。

## 7. 可迁移到 Codex Director 的机制

### 7.1 原生边界

必须保留：

- `NavigationSplitView` 与原生 macOS Sidebar；
- 系统窗口、工具栏、Picker、List 选择、键盘和焦点行为；
- SF Pro 语义字体；
- Light/Dark、Increase Contrast、Reduce Transparency、Reduce Motion；
- 数据口径、隐私、缓存、索引和六页导航。

Fulcrum 只影响工作区内容的视觉编排，不替代 macOS 的应用结构。

### 7.2 首页应采用三种不同的区段语法

首页三个模块不应继续共享同一种圆角面板语法。

#### 01 额度：开放式数据舞台

- 使用一个明显的不对称主舞台，而不是“圆环卡 + 柱状图卡”。
- 剩余额度成为第一视觉数字；重置时间、记录时间降为窄信息列。
- 七日柱图是主视觉锚点，使用精修轴线、柱顶标注、周期变化符号和缺测态。
- 允许一处大型周期轨道或弧线图形，表达“额度属于一个重置周期”，但不得伪造精度。
- 环境光只在该舞台的一侧出现，帮助平衡图表，不在每个柱子背后发光。

#### 02 能力规模：指标带而非四张同质卡片

- 四类能力可以构成连续的指标带或被细线分隔的四个节拍。
- 类别图标需要形成统一但有细节的系统；SF Symbol 可作为语义原型，最终由项目图标规范统一光学尺寸和容器。
- 大数字是视觉主体，图标只提供类别识别。
- 可点击状态通过边界、底部强调线和焦点环表达，不让四张卡都像四个主按钮。

#### 03 使用排行：比较式信息账本

- 三类排行在宽屏形成顶部对齐的比较账本，而非三个独立高卡片。
- 组间由垂直细线或背景明度差区分；行内由名称、序号、次数和比例条建立稳定节奏。
- 每组可有自己的蓝、冰蓝、薄荷节奏，但底层文字和线条仍以灰白为主。
- 长名称保留主要宽度，推断标识是证据语义，不作为装饰徽章堆叠。

### 7.3 图表精致度的转译要求

图表不应只换颜色。必须同时设计：

- 轴线、基线和网格线的对比层级；
- 0%、100%、缺测、过期和周期变化的独立图形语法；
- 柱宽、圆角、标签距离和 7 日连续日期节奏；
- hover、键盘焦点和 VoiceOver 的每日数值读取；
- Light/Dark 下的视觉重量；
- 窗口变窄后的标签策略，而不是简单压缩。

允许使用蓝—冰蓝—薄荷的冷色序列，但不能把橙色周期变化简单替换为另一种颜色；变化必须同时使用形状或文字。

### 7.4 图标系统的转译要求

建立两级图标语言：

1. **功能 Glyph**：导航、筛选、排序、展开、刷新、错误。使用 SF Symbols，保持原生。
2. **内容 Pictogram**：Agent、Skill、Installed Skill、Plugin、额度周期和索引状态。以 SF Symbols 为语义基础，统一 20/24 pt 光学框、线宽、圆角和容器；需要大型视觉锚点时制作原创项目线稿，不放大普通 SF Symbol 充当插画。

图标不得重复朗读相邻文字，也不得成为唯一的状态信号。

### 7.5 共享视觉语言，不共享单一组件模板

可以共享：

- 画布与环境光 token；
- 标题尺度与关键字着色逻辑；
- 主/次文字对比；
- 细分隔线；
- 卡片描边与不对称角；
- 主按钮；
- 图标光学规范；
- 状态和可访问性规则。

不应强制共享：

- 每个区段的容器形状；
- 每个页面的网格数量；
- 每个模块的标题位置；
- 每个数据块是否使用卡片；
- 每个视觉锚点的构图。

## 8. 不可照搬的内容

- Fulcrum 的 Logo、品牌字样、复古电脑、行业插画、案例图像和认证图标；
- `Neue Montreal` 字体文件或对它的像素级仿制；
- 网站式顶部导航、营销 Hero、客户证言、奖项、联系表单和页脚；
- 网页横向滚动控制在原生列表中的强行复刻；
- 持续视差、滚动驱动故事或妨碍桌面工作效率的装饰动画；
- 精确复制原站渐变坐标、资产构图、卡片切角或段落顺序。

## 9. Codex Director 视觉令牌候选

以下是角色建议，不是批准的最终数值。最终值需在原生窗口中以 Light/Dark 和对比度测试收敛，不能直接复制源站 CSS。

| 角色 | 意图 |
| --- | --- |
| `canvas.nearBlack` | 深色主画布，保留接近纯黑的沉静基底 |
| `canvas.light` | 浅色模式的冷白/浅灰等价画布 |
| `ambient.blue` | 低频蓝色空间光，单区段单侧使用 |
| `ambient.teal` | 深海青空间光，平衡蓝色而非取代语义色 |
| `accent.electricBlue` | 主要强调、选中细线、图表主序列 |
| `accent.ice` | 次级数据序列与渐变中段 |
| `accent.mint` | 第三数据序列与主按钮终点 |
| `text.high` | 近白/近黑主文字 |
| `text.mid` | 说明与数据上下文 |
| `text.low` | 时间、脚注、补充标记 |
| `rule.section` | 长距离低对比分隔线 |
| `rule.container` | 卡片/图表边界，强于区段线 |
| `fill.panel` | 仅在内容需要容器时使用的不透明面板 |
| `fill.selected` | 选中洗色，必须同时有边界或原生选择信号 |
| `action.primaryGradient` | 电蓝 → 冰蓝 → 薄荷的填充主操作 |

## 10. 后续高保真设计工作流

### 阶段 A：参考机制板

UI Designer 首先制作一页“机制板”，不是方案页面。必须展示：

- 标题尺度与双色文字；
- 画布光场；
- 分隔线、面板边界和不对称角；
- 填充主按钮；
- 两级图标语言；
- 图表轴线、柱体、标注和缺测态；
- 三种不同的区段构图缩略图。

Root 先审批机制是否准确，不审批功能布局。

### 阶段 B：首页全彩高保真方向

- 使用真实 1280×800 应用工作区比例，不生成网站长页。
- 保留真实 Sidebar 占位和 macOS 窗口关系，但不把 Sidebar 当作视觉设计重点。
- 直接输出全彩 Dark 版本；同时提供关键模块的 Light 对应关系。
- 必须改变三个模块的轮廓和扫描路径，不能只换 token。
- 每个方案只能有一个明确的构图命题，不能混合多套风格。

### 阶段 C：确定性视觉合同

选中方向后，先写清楚再实现：

- 布局尺寸、断点与最大宽度；
- 标题、数字和正文语义字号；
- 光场位置和最大面积；
- 图表构造；
- 图标网格；
- 卡片使用/不使用的明确位置；
- 所有状态与可访问性行为；
- 可转译为 SwiftUI 的组件边界。

### 阶段 D：Frontend Developer 实现

实现必须以选中高保真稿和确定性合同为准。不得只根据“Fulcrum 风格”“更精致”或一组色值自由发挥。

## 11. 视觉验收硬门槛

以下任一项成立即判定视觉重构未通过：

1. 缩小截图后，页面轮廓与当前版本基本相同，只是颜色、边框或间距变化。
2. 三个首页模块仍使用同一种通用圆角面板结构。
3. 参考被概括为“黑底 + 青色渐变 + 大标题”。
4. 没有任何 Codex Director 专属视觉锚点。
5. 图表仍是默认 Swift Charts 外观，只换了 accent color。
6. 大型插画只是放大的 SF Symbol。
7. 主按钮仍是描边或纯单色，且没有明确主次层级。
8. 页面依赖大量发光、玻璃或阴影掩盖普通构图。
9. Light 模式只是把背景反白，没有重新校准光场、描边和文字对比。
10. 高保真稿使用虚构指标、虚构资源或违反当前数据语义。
11. 键盘、焦点、VoiceOver、Increase Contrast 或 Reduce Motion 因视觉效果退化。
12. 只检查代码和 token，没有真实窗口截图的同尺寸视觉比较。

通过需要同时满足：

- 信息语义正确；
- macOS 行为原生；
- 三个模块轮廓明确不同；
- 标题尺度、环境光、视觉锚点和内容密度形成清晰节奏；
- 图表与图标具有项目专属工艺；
- 1280×800、720×480 和宽窗口均保持设计意图；
- Dark/Light 都经过真实截图检查。

## 12. 研究结论

Fulcrum 的优秀不在于某个渐变色值，而在于它把品牌视觉、编辑式排版、技术图像和区段结构整合成同一套空间叙事。Codex Director 下一轮首页设计需要从“给现有模块换皮”转向“为额度、能力规模和能力使用分别设计最合适的视觉语法”，再用共同的光色、字体层级、细线、按钮和图标系统把它们统一起来。

这份文档是后续 UI Designer 的参考约束。它不授权复制 Fulcrum 的品牌资产，也不要求把桌面应用做成营销网站。
