# Security Policy

## Supported versions

Security fixes are provided for the latest public release and the current `main` branch.

## Reporting a vulnerability

Use GitHub private vulnerability reporting for security and privacy issues. Do not open a public issue containing exploit details, credentials, session content, capability source, private paths, or exported packages.

Include the affected version, macOS version, a minimal synthetic reproduction, expected behavior, and observed impact. Remove account names, machine paths, project names, prompts, command arguments, and raw logs.

## Release trust model

Community builds are ad-hoc signed and are not notarized by Apple. Verify the release checksum and GitHub artifact attestation. A successful checksum proves file integrity relative to the published checksum; it does not prove Apple identity or malware review.
